# Papercuts from browser audit

## Evidence-backed findings

- `e2e/real-database-payment.spec.ts` удаляет существующие платежи, allocations, command и audit records для выбранного класса при подготовке fixture, но не восстанавливает их, если браузерный шаг падает до создания нового платежа. На текущем прогоне это удалило `payment-1`.
- `playwright.config.ts` при `DISPOSABLE_E2E=1` включает real-database specs вместе с disposable specs. Эти тесты требуют реальные учетные данные и существующую рабочую базу, поэтому disposable-прогон дал ложные падения для real smoke/payment.
- `e2e/ft-007-profile-routes.spec.ts` ожидает ISO-строку регистрации, тогда как UI корректно выводит локализованную дату через `formatDateTime`; проверка падает из-за несовпадения контракта теста и отображения.
